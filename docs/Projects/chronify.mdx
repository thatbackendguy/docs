      <h2>Large media libraries need cautious migration</h2>
      <p className="sectionLead">
        Photo and video collections often live across laptops, external drives, camera dumps, phone exports, screenshots, and chat app folders. Chronify organizes those collections without loading media contents into memory and without risky, irreversible first runs.
      </p>
    </div>
    <div className="caseGrid">
      <article className="caseCard">
        <h3>Guided setup</h3>
        <p>Run <code>chronify</code> with no arguments and answer a few questions. It prints the equivalent command at the end so the run can be repeated later.</p>
      </article>
      <article className="caseCard">
        <h3>Preview, confirm, undo</h3>
        <p>Chronify shows where every file would go, asks <code>[y/N]</code> before acting, and writes a CSV manifest that can reverse the run.</p>
      </article>
      <article className="caseCard">
        <h3>Safe file handling</h3>
        <p>Existing files are never overwritten, copies are written to a temp file first, and cross-drive moves are verified before the original is deleted.</p>
      </article>

  <section className="caseSection">
    <div className="caseHeader">
      <p className="sectionKicker">Date detection</p>
      <h2>Metadata first, filename second</h2>
      <p className="sectionLead">
        Chronify chooses dates in a layered order, so files like <code>IMG_1234.HEIC</code> or <code>IMG_1234.MOV</code> with no date in the name still land in the right folder.
      </p>
    </div>
    <div className="caseGrid">
      <article className="caseCard">
        <h3>1. Built-in readers</h3>
        <p>Native parsers read only the bytes that hold dates: Exif in JPEG, HEIC/AVIF, RAW (CR2, CR3, NEF, ARW, DNG, RAF…), PNG and WebP, plus MP4/MOV, AVI, and MKV/WebM headers. Multi-GB videos stay fast.</p>
      </article>
      <article className="caseCard">
        <h3>2. Optional tools</h3>
        <p>With <code>-metadata auto</code>, Chronify also uses <code>exiftool</code>, <code>ffprobe</code>, or macOS Spotlight if present, which helps with formats like AVCHD <code>.mts</code>.</p>
      </article>
      <article className="caseCard">
        <h3>3. Fallbacks</h3>
        <p>It then checks camera, phone, screenshot, and WhatsApp-style filenames, then the file's modified time, and finally routes the file into <code>_unknown_date/</code>.</p>
      </article>
    </div>
  </section>

  <section className="caseSection">
    <div className="caseHeader">
      <p className="sectionKicker">Controls</p>
      <h2>Useful flags</h2>
    </div>
    <div className="caseGrid">
      <article className="caseCard">
        <h3>Layout</h3>
        <p><code>-by</code> chooses <code>year</code>, <code>month</code>, or <code>day</code>.</p>
        <p><code>-month-format</code> sets month folder names.</p>
        <p><code>-unknown-dir</code> names the folder for undated files.</p>
      </article>
      <article className="caseCard">
        <h3>Execution</h3>
        <p><code>-apply</code> performs changes; omitted means preview only.</p>
        <p><code>-mode</code> chooses <code>move</code> or <code>copy</code>; <code>-yes</code> skips confirmation for scripts.</p>
        <p><code>-undo</code> reverses a run from its manifest.</p>
        <p><code>-conflict</code> chooses <code>rename</code> or <code>skip</code> for duplicates.</p>
      </article>
      <article className="caseCard">
        <h3>Dates and filters</h3>
        <p><code>-media</code> selects <code>all</code>, <code>images</code>, or <code>videos</code>.</p>
        <p><code>-metadata</code> selects <code>auto</code>, <code>native</code>, or <code>never</code>.</p>
        <p><code>-min-year</code> and <code>-max-year</code> bound accepted dates.</p>
        <p><code>-json</code> emits machine-readable events for apps.</p>
      </article>
    </div>
  </section>
